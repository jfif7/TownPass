### 1. 專案簡介 / Project Overview

- 專案目的與想解決的問題

  - 本專案旨在數位轉型廣受市民喜愛的「集章活動」，將其深度整合至 「台北通」 應用程式中。我們的核心目標是建立一個具備高度互動性、探索性與靈活性的一站式集章服務平台，藉由最新的行動技術，大幅提升市民參與公共活動的體驗與樂趣，同時為市府活動管理帶來效率革新。

- 想解決的問題

  1. 實體集章限制多： 傳統紙本或單一 QR Code 集章缺乏互動性、容易遺失或損壞，且活動資料難以即時更新或統計。
  2. 市民參與體驗單一： 缺乏新穎的探索與尋寶機制，降低了市民持續參與活動的動機與樂趣。
  3. 市府活動管理低效： 市府部門辦理集章活動時，需耗費大量人力進行前置設計、後續統計與資料彙整，系統缺乏統一且靈活的活動設計介面。

- 核心功能摘要
  多技術集章支援： 整合 NFC 感應、QR Code 掃描 及 互動式問答（Quiz-based）等多元集章技術。
  即時尋寶互動機制： 借鑒 AirTag 的使用情境，運用 GPS 及相機鏡頭技術，讓市民在集章過程中能即時查看目標點的方向與距離。

### 3. 安裝與執行方式 / Installation & Run

本地端執行方式

執行本專案前，請確認您的環境已安裝以下必要組件：

- Node.js: v19
- Python: 3.10 或以上
- Docker

步驟說明：

1. 複製專案庫：

```
git clone https://github.com/taipei-doit/townpass2025-stampquest
```

2. 使用 docker compose 啟用前端後端 DB container

```bash
# 啟動開發環境
docker-compose -f docker-compose.dev.yml up -d

# 查看開發環境日誌
docker-compose -f docker-compose.dev.yml logs -f

# 停止開發環境
docker-compose -f docker-compose.dev.yml down
```

3. 執行資料庫遷移

```bash
docker-compose exec backend alembic upgrade head
```

4. 生成假資料

```bash
# 方式 1: 簡易版 - 快速生成一組測試資料（不清空現有資料）
docker-compose exec backend python seed_simple.py

# 方式 2: 完整版 - 生成大量測試資料（會清空所有現有資料）
docker-compose exec backend python seed.py
```


5. 訪問應用程式

完成上述步驟後，您可以透過以下連結訪問：

- **前端應用**：http://localhost:3000/
- **API 文件**：http://localhost:8000/docs

6. 與 TownPass 對接

您也可以在本地端透過 Android Studio 以及模擬器在 Townpass 內訪問本服務。

二、若使用 AI，需額外補充的項目（AI Usage Declaration）

1. 使用到的 AI 模型
   Gemini：Gemini 2.5 Pro 
   Claude：Claude Sonnet 4.5
2. 使用範圍
  - 程式碼產生：
    - 前後端 API 雛形：約佔總程式碼的 50%
    - 文字生成：README、規格書、文件等說明文的初稿撰寫與潤飾
    - 程式碼註釋與文件翻譯
    - 假資料生成腳本
3. AI 產生內容如何被驗證或修改
  - 人工 Code Review： 所有 AI 產生的程式碼都經過至少一位組員的人工 Code Review，確保邏輯正確性與符合專案風格。
  - 安全性檢查： 特別針對資料庫操作及使用者輸入驗證的 AI 程式碼進行安全性檢查，避免潛在的 SQL Injection 或 XSS 漏洞。
  - AI 產出後 Refactor： 絕大多數 AI 產出的程式碼塊被整合進現有框架時，都經過 Refactor (重構)，以提高可讀性和模組化程度。
4. 與 AI 相關的限制或風險
  - 目前模型可能產生錯誤資訊 (幻覺/Hallucination)： 在使用 AI 進行資料格式轉換或外部 API 參數查詢時，發現偶爾會產生錯誤或過時的資訊，需要人工進行雙重確認。
  - 自動化程式碼生成可能會遺留安全性漏洞： 儘管進行了安全性檢查，仍可能存在 AI 遺留的次要安全風險，我們已盡力在核心邏輯上進行人工審查。
  - 資料來源與版權聲明： 對於 AI 生成的文字內容，我們已確保其不會直接抄襲公開文獻。
  - 是否涉及敏感資料 (應避免)： 在與 AI 互動過程中，我們未曾輸入任何專案機密、使用者個人資料或未公開的 API 金鑰。
